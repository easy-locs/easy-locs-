IMPLEMENTATION DETAILS
A. support-email-webhook
- validates webhook secret via SUPPORT_EMAIL_WEBHOOK_SECRET
- parses multipart/form-data and JSON payloads
- extracts sender, subject, body, message-id, in-reply-to, references
- normalizes subject for thread matching
- creates or updates email thread
- stores inbound email in email_messages
- stores inbound log in email_delivery_logs
- updates thread status to processing
- loads conversation history from email_messages
- sends full context to OpenAI API using OPENAI_API_KEY
- creates email_ai_replies record
- sends outbound reply through SendGrid from contact@easy-locs.com
- stores outbound email in email_messages
- stores provider response in email_delivery_logs
- updates thread / ai reply status to replied or failed
- routes sensitive keywords to human_review instead of auto-send

B. support-email-reply
- requires authenticated user
- restricts override to Easy-Locs staff domain or privileged org member
- supports manual send or draft/human_review mode
- can approve/use existing AI reply or custom human reply text
- sends outbound email from contact@easy-locs.com
- stores outbound email in email_messages
- stores delivery result in email_delivery_logs
- updates email_ai_replies reviewed_by / approved_at / sent_message_id
- updates thread status to replied or failed

C. frontend contract
- src/lib/support-email/supportEmailApi.ts
Added provider-agnostic helper methods:
- listSupportThreads()
- getSupportThreadMessages(threadId)
- sendSupportHumanReply(payload)

This keeps frontend contracts provider-agnostic and aligned with the existing Easy-Locs architecture.
